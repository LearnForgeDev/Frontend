# Вход и сессия

Источники: [AuthFlowContext](../../src/Services/Auth/contexts/AuthFlowContext.tsx), [AuthLayout](../../src/Services/Auth/Pages/AuthLayout/AuthLayout.tsx), [восстановление сессии](../../src/Services/Auth/hooks/useRestoreSession/useRestoreSession.ts), [HTTP-клиент](../../src/Endpoints/factory/factory.ts).

Предусловия: чистый контекст для гостя; существующий аккаунт с известными тестовыми данными для входа; уникальное имя для регистрации. Серверные операции проверять с настоящим API.

## Авторизация и регистрация

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| AUTH-01 | P0 | Гостем открыть `/`, затем `/auth` | Оба адреса приводят к `/auth/login`; видны имя, пароль и кнопка «Войти» |
| AUTH-02 | P0 | На входе перейти по «Зарегистрироваться», затем вернуться по «Войти» | Открываются соответствующие формы без защищённого интерфейса |
| AUTH-03 | P0 | Заполнить верные данные; отправить форму кнопкой; повторить отдельным тестом через Enter | После входа открывается `/app`, затем «Сегодня» доступной школы; для аккаунта без школ — `/onboarding` |
| AUTH-04 | P0 | Ввести неверный пароль или неизвестное имя | Форма остаётся открытой, есть «Не удалось войти»; сессия не появляется, поля доступны для исправления |
| AUTH-05 | P1 | Отправить пустую форму; затем заполнить только одно обязательное поле | Вход не выполняется; браузер/форма показывает обязательность ввода, защищённые страницы недоступны |
| AUTH-06 | P1 | Ввести пароль, нажать «Показать пароль», затем «Скрыть пароль» | Меняется `type` поля, введённое значение сохраняется; повторить для доступных парольных полей регистрации |
| AUTH-07 | P0 | Зарегистрировать уникальное имя с совпадающими паролями | Создан реальный пользователь; открывается онбординг без бесконечной проверки сессии; повторный вход этим аккаунтом работает |
| AUTH-08 | P1 | На регистрации указать разные пароли; затем исправить; отдельно зарегистрировать уже занятое имя | Несовпадение показывает «Пароли не совпадают» без отправки регистрации; занятое имя даёт понятную ошибку без авторизации под чужим аккаунтом |
| AUTH-09 | P1 | После подтверждённого входа открыть `/auth/login` и `/auth/register`; отдельно отключить сеть во время входа | Авторизованный пользователь перенаправлен в `/app`; при сетевой ошибке форма доступна для повторной попытки, нет зависшего состояния загрузки |

## Восстановление и завершение сессии

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| SESSION-01 | P0 | Войти, открыть раздел школы, перезагрузить страницу; повторить в новом контексте с корректным `storageState` | Сначала backend подтверждает refresh-токен; затем появляется школа и сохраняется выбранная школа; один localStorage не считается авторизацией |
| SESSION-02 | P0 | Для каждого защищённого маршрута открыть URL гостем | Переход к входу; нет кратковременного показа защищённого интерфейса и данных. Включить онбординг и `/developer` |
| SESSION-03 | P0 | Для `/` и прямого URL уроков подготовить повреждённый JSON либо запись пользователя без токенов | Локальная сессия очищена; открыта форма входа; навигация школы и редактор не монтировались |
| SESSION-04 | P0 | Повторить предыдущий вход с поддельным JWT с будущим сроком и с просроченным JWT плюс недействительным refresh | Backend отклоняет сессию; очищены локальные данные авторизации, показан вход без защищённых данных |
| SESSION-05 | P1 | Сохранить реальный refresh-токен, дождаться/подготовить истечение access-токена, вызвать защищённое чтение | Refresh выполняется, исходная операция успешно повторяется; пользователь остаётся в своей школе; нет бесконечного цикла запросов |
| SESSION-06 | P0 | С корректной сохранённой сессией открыть приложение при недоступном backend; восстановить сеть и нажать «Повторить» | До подтверждения сессии показана блокирующая ошибка; защищённый UI скрыт, сетевая ошибка не превращается в ложный logout; после повтора сессия восстановлена |
| SESSION-07 | P0 | Войти, открыть профиль, нажать «Выйти», перезагрузить; затем открыть защищённый URL и вернуться назад | Сессия удалена, открывается вход; история браузера не восстанавливает доступ к данным |
| SESSION-08 | P1 | Управляемо задержать refresh/защищённый запрос; выполнить выход или сменить аккаунт до его завершения; затем отпустить ответ | Поздний ответ не возвращает прежнего пользователя; роли и данные не смешиваются. Нужна управляемая задержка тестового стенда |
| SESSION-09 | P1 | При истёкшем access-токене инициировать несколько чтений; отдельно вызвать недействительный refresh | Нет каскада refresh и повторных выходов; исходные чтения либо успешно восстановлены, либо пользователь однократно возвращён ко входу |

После logout и входа под другим аккаунтом дополнительно выполнять COMMON-05: этот сценарий проверяет кеш данных, а не только запись сессии.

## Ограничение возврата к исходной ссылке

Текущий `ProtectedRoute` переводит гостя на вход без сохранения исходного адреса, а подключённый `AuthFlowContext` после входа открывает `/app`. Автоматический возврат к приглашению, комнате или конкретному уроку после логина — **цель**, а не существующая гарантия. Флоу с приглашением гостю описан в INV-04; его нельзя объявлять работающим только по наличию неиспользуемого `useLogin`.
