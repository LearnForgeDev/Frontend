# Расписание и звонки

Источники: [экран расписания](../../src/Services/Scheduling/SchedulePageContent.tsx), [форма занятия](../../src/Services/Scheduling/components/CreateEventModal/CreateEventModal.tsx), [окно входа](../../src/Services/Scheduling/hooks/useJoinWindow/useJoinWindow.ts), [экран звонка](../../src/Services/Schools/CallsPage/CallsPage.tsx), [приглашения в звонок](../../src/Services/Schools/CallsPage/hooks/useBroadcastCallInvite/useBroadcastCallInvite.ts).

Предусловия: преподаватель/владелец и ученики школы; фиксированная дата/часовой пояс теста; подготовленные реальные события. Для UI-границ времени пользоваться часами браузера, для серверных разрешений — согласованными данными backend.

## Расписание

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| SCHEDULE-01 | P0 | Открыть расписание со своими событиями, затем пустое расписание | События соответствуют backend, дата и время отображаются локально; пустой календарь не заменяет ошибку |
| SCHEDULE-02 | P1 | Переключить неделю/день/список, предыдущий/следующий период, «Сегодня», выбрать дату в мини-календаре | Меняются период и представление одних данных; нет исчезновения событий из-за смены представления |
| SCHEDULE-03 | P0 | Teacher/Owner нажать «Новое занятие», заполнить название, описание, дату, начало и конец, создать | Событие сохранено с UTC-интервалом и непустым room; участники соответствуют текущему контракту, событие видно после reload и у приглашённого ученика |
| SCHEDULE-04 | P1 | Нажать свободный слот календаря и создать занятие | Форма получает выбранную дату и время начала, конец на час позже по текущему шаблону; сохранённый интервал соответствует выбору |
| SCHEDULE-05 | P1 | Отправить пустое название/дату/время; конец равен началу или раньше; исправить данные | Невалидный POST/PUT не отправлен, показана ошибка; исправление позволяет сохранить |
| SCHEDULE-06 | P0 | Открыть существующее событие, перейти к редактированию, изменить дату/время/описание, сохранить | Backend и календарь показывают изменения после reload; room и прежний состав участников не теряются |
| SCHEDULE-07 | P1 | В карточке изменить название inline; отдельно отменить через доступное действие и воспроизвести ошибку сохранения | Подтверждённое название сохранено на backend; отмена/ошибка не выдаёт новый текст за сохранённый; остальные поля не меняются |
| SCHEDULE-08 | P0 | Открыть карточку события и нажать удаление | Событие удалено из backend и календаря, карточка закрыта после успеха; ошибка удаления оставляет событие доступным. Сейчас удаление выполняется сразу, отдельного подтверждения в этом экране нет |
| SCHEDULE-09 | P1 | Открыть `/schedule?eventId=…` для существующего события, затем отсутствующего; закрыть карточку | Нужное событие раскрыто, календарь приведён к его дате; отсутствующий ID не открывает чужую карточку и не роняет экран |
| SCHEDULE-10 | P1 | В событии нажать добавление в Google Calendar | Ссылка содержит название и UTC-интервал нужного события; открывается отдельно. Логин в Google и фактическое добавление в аккаунт не входят в базовый тест |
| SCHEDULE-11 | P0 | Учеником открыть календарь и карточку; отдельно напрямую отправить create/update/delete | Нет действий управления и создания по слоту; backend запрещает изменения, события сохраняются |
| SCHEDULE-12 | P1 | Вызвать ошибку списка/сохранения; отдельно ошибку загрузки учеников при создании; затем восстановить доступ и повторить | Есть понятная ошибка и повтор; новая форма не создаёт занятие с неизвестным составом, пока ученики не загружены; ошибка мутации сохраняет введённые значения |

Текущая форма создания автоматически включает учеников школы, а при редактировании сохраняет существующих участников. Ручного выбора отдельных учеников и флоу регулярных занятий здесь нет: не придумывать эти шаги теста.

События с пересечением по времени и датой на границе суток включать в SCHEDULE-01/02: в сетке доступны обе карточки, в списке порядок и интервал корректны. Тесты UTC/local выполнять минимум для двух фиксированных часовых поясов.

## Вход в комнату

По текущему `useJoinWindow` преподаватель/владелец может войти до начала, пока событие не закончилось. Для ученика кнопка открывается за `STUDENT_JOIN_WINDOW_MINUTES` (сейчас 5 минут) до начала. После конца или при невалидном интервале вход закрыт. Это правило кнопки; серверные правила токена проверять отдельно.

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| CALL-01 | P0 | Учеником открыть событие раньше окна, на границе открытия, во время и после конца; повторить Owner/Teacher | Кнопка меняется «Скоро» → «Войти» → «Завершено» без reload; до конца преподавателю доступен ранний вход; невалидный интервал не разрешает вход |
| CALL-02 | P0 | Из «Сегодня»/карточки события нажать «Войти»; повторить прямой авторизованной ссылкой `calls?room=…&title=…` | Открыта комната правильной школы с правильным названием, выполняется реальная выдача токена для этого room |
| CALL-03 | P0 | Участником запросить комнату; затем гостем, посторонним и пользователем с недостаточными правами | Backend выдаёт токен только разрешённому пользователю; проверяется реальный отказ для остальных. Одного успешного запроса владельца недостаточно |
| CALL-04 | P1 | Открыть `/calls` без room и с пробельным room; затем получить отказ/сетевую ошибку токена и нажать «Попробовать снова»/«Закрыть» | Без комнаты — «Звонок не выбран»; ошибка видна и не вызывает бесконечный запрос; повтор пытается открыть тот же room, закрытие возвращает к пустому состоянию |
| CALL-05 | P1 | На рабочем Jitsi-стенде войти, включить/выключить fullscreen, завершить звонок; затем перейти в другую комнату | Встроенная конференция работает, fullscreen переключается; старая конференция освобождена, завершение возвращает в приложение, новая комната не показывает прежний iframe |
| CALL-06 | P0 | На странице комнаты нажать «Пригласить», выбрать участников, отправить; проверить в личных чатах получателей | Приглашения отправлены только выбранным участникам, без самого отправителя; ссылки содержат ту же школу/комнату/название; получатель может открыть комнату |
| CALL-07 | P1 | Отправить приглашение без получателей; отдельно частичный и полный отказ доставки; вызвать ошибку `external_api.js` | Пустая отправка не объявлена доставкой, число успешных приглашений соответствует реальности; полный отказ/ошибка подключения видны; страница остаётся управляемой |
| CALL-08 | P0 | **Отдельный медиа-стенд:** два пользователя входят в одну конференцию с тестовыми камерой/микрофоном; отключают/включают устройства и выходят | Оба действительно подключены и получают медиа; выход освобождает устройства. В текущем CI с `meet.invalid` этот сценарий невыполним и не покрыт тестом выдачи токена |
