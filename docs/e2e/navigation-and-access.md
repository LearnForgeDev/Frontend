# Навигация, права, «Сегодня» и профиль

Источники: [AppShell](../../src/Services/AppShell/AppShell.tsx), [список навигации](../../src/Services/AppShell/AppShell.const.ts), [возможности ролей](../../src/Services/AppShell/utils/getSchoolCapabilities.ts), [доступ к школе](../../src/Router/SchoolAccessGuard.tsx), [«Сегодня»](../../src/Services/Today), [профиль](../../src/Services/Profile/ProfilePage.tsx).

## Матрица прав

| Возможность | Owner | Teacher | Student |
| --- | --- | --- | --- |
| Открыть свою школу, «Сегодня», уроки, материалы, чаты, расписание | Да | Да | Да |
| Создать урок, редактировать на desktop, управлять расписанием | Да | Да | Нет |
| Открыть «Ученики», создать приглашение ученика | Да | Да | Нет |
| Создать приглашение преподавателя, видеть сводку школы | Да | Нет | Нет |
| Создать курс | Да, если каталог не заблокирован | Да, если каталог не заблокирован | Нет |
| Управлять конкретным курсом | По серверному `canManage` | По серверному `canManage` | По серверному контракту, без назначения административных прав на клиенте |
| Подключиться к звонку | По правилам комнаты и backend | По правилам комнаты и backend | По правилам комнаты и backend |
| Одобрять школы | Отдельные служебные права backend, роль владельца школы их не заменяет | Отдельные служебные права backend | Отдельные служебные права backend |

Для нескольких ролей применяются объединённые возможности: Owner/Teacher дают `canTeach`, только Owner — `canManageSchool`. Материалы и чаты сейчас не скрывают действия по `canTeach`; разрешение операций нужно проверять на реальном backend, не переносить сюда правила уроков автоматически.

## Навигация

Предусловия: школа A с каждой ролью, школа B с отличающимися данными и ролью; пользователь с двумя школами и новый пользователь без школ.

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| NAV-01 | P0 | Открыть `/app`; затем корень своей школы | Выбрана сохранённая доступная школа или первая доступная; корень школы переходит на `/today`; отсутствующая сохранённая школа не создаёт цикл |
| NAV-02 | P0 | Открыть «Мои школы», выбрать A; повторить через переключатель в шапке | Список соответствует backend, активная школа отмечена; открыт `/today` A, выбор сохраняется после reload |
| NAV-03 | P0 | Из A перейти в B, открыть уроки, курсы, материалы, чаты, расписание; перезагрузить | URL, заголовки, данные и доступные действия относятся к B; данные/роль A не остаются. Включить сценарий Teacher в A → Student в B |
| NAV-04 | P1 | В «Моих школах» нажать «Добавить школу»; отдельно проверить пустой список и ошибку загрузки с повтором | Открыт онбординг; пустой список отличается от ошибки; «Повторить» после восстановления загружает школы |
| NAV-05 | P0 | На desktop последовательно открыть все пункты «Разделы школы» | Открываются «Сегодня», «Уроки», «Курсы», «Расписание», «Чаты», «Материалы» и допустимые «Ученики»; текущий пункт выделен, school ID сохранён |
| NAV-06 | P1 | На mobile открыть основные разделы и меню «Ещё», выбрать курс/материалы/учеников, затем профиль | Доступны те же разрешённые разделы; меню закрывается после выбора, нижняя навигация не перекрывает действия |
| NAV-07 | P1 | Авторизованным открыть `/admin`, `/profile`, `/Lessons`, `/Lessons/L`, `/admin/schools/S`, `/admin/schools/S/lessons`, `/admin/schools/S/calls`, `/admin/schools/S/settings` | `/admin` и оба `/Lessons` ведут в `/app`; `/profile` → `/app/profile`; старые школьные пути переводятся в новые, `calls` → `schedule`, `settings`/пустой путь → `today`. Старый ID урока не восстанавливается через `/Lessons/L` |
| NAV-08 | P1 | Открыть неизвестный адрес и `/403`; воспользоваться доступным действием возврата | Соответственно показаны 404 и страница запрета; приложение не падает, возврат ведёт к существующей странице |
| NAV-09 | P1 | На «Учениках» проверить список, группы, пустое состояние, ошибку/повтор; в строке ученика нажать «Написать» | Данные соответствуют школе; открывается `/chats?user=…` с нужным собеседником; ID отсутствующего ученика не создаёт случайный чат |

## Доступ и изоляция

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| ACCESS-01 | P0 | Участником A открыть прямые URL реальной чужой B и случайной школы; запросить её данные через API | UI возвращает на `/app/schools`; backend даёт отказ/отсутствие ресурса, сведения B не раскрыты. Несуществующий UUID не заменяет проверку чужой существующей школы |
| ACCESS-02 | P0 | Каждой ролью открыть уроки и `/students`; учеником вручную добавить `?edit=true` к уроку | Owner/Teacher видят создание и учеников; Student не видит управление, `/students` переходит к `/today`, редактор остаётся readonly |
| ACCESS-03 | P0 | Учеником/посторонним отправить напрямую операции создания/изменения урока, курса, расписания, приглашения и служебной заявки | Backend запрещает недопустимые операции; после reload нет изменений. Проверять реальные ограничения каждого контракта, а не только отсутствие кнопки |
| ACCESS-04 | P1 | Открыть сохранённый URL после отзыва членства или смены роли, затем перезагрузить | После обновления данных школы доступ/действия соответствуют новой роли; старые разрешения не обходят backend |

## «Сегодня»

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| TODAY-01 | P0 | Подготовить ближайшее занятие, сегодняшние и будущие события, недавние уроки; открыть `/today` | Имя/дата, ближайшее занятие, список за сегодня и недавние уроки соответствуют данным и часовому поясу, чужих событий нет |
| TODAY-02 | P1 | Открыть школу без событий и уроков | Показаны пустые состояния, нет выдуманного ближайшего занятия и нерабочего входа в комнату |
| TODAY-03 | P0 | Преподавателем нажать «Создать урок», затем в отдельном тесте «Запланировать»; открыть недавний урок и календарь ближайшего события | Создание ведёт в реальный урок; планирование открывает расписание с формой; карточки ведут к нужным ID, событие раскрывается через `eventId` |
| TODAY-04 | P1 | Открыть страницу владельцем, преподавателем и учеником | Действия создания доступны только canTeach; сводка числа учеников — только владельцу, число берётся из школы |
| TODAY-05 | P1 | Поочерёдно нарушить чтение расписания, уроков, сводки | Ошибка показана в соответствующем блоке, остальные данные/навигация работают; загрузка не выглядит как пустой успешный список |

## Профиль

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| PROFILE-01 | P1 | Открыть профиль пользователем с несколькими школами и разными ролями | Имя, доступные контакты и роли соответствуют текущему аккаунту; отсутствующие контакты не заменены чужими данными |
| PROFILE-02 | P1 | Подготовить ближайшее событие активной школы; нажать переход к календарю | Открыт календарь правильной школы с правильным `eventId` |
| PROFILE-03 | P1 | Проверить отсутствие занятий/школ и отказ чтения школ/расписания | У каждого блока есть соответствующее пустое состояние или ошибка; нет ложного занятия |
| PROFILE-04 | P0 | Нажать «Выйти» | Выполнен SESSION-07; данные профиля прежнего аккаунта не отображаются после нового входа |
| PROFILE-05 | P0 | Открыть профиль общей кнопкой «Открыть профиль» из школы, выбора школы в онбординге и ожидания заявки; повторить в состояниях загрузки/ошибки ожидания; из профиля выйти | Во всех состояниях доступен `/app/profile` с текущим аккаунтом; можно выйти даже без готовой школы и повторно войти другим пользователем; на mobile доступна кнопка с тем же именем |

Редактирование профиля и загрузка аватара не становятся флоу только из-за существования endpoint: в подключённом профиле нет такой формы.
