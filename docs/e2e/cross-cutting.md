# Общие проверки и сквозные пути

Эти сценарии дополняют проверки конкретных страниц. Ошибки и два пользовательских контекста подготавливать по [правилам окружения](environment.md). Строки с ожидаемыми защитными свойствами описывают критерий теста, а не утверждение о его прохождении в текущем приложении.

## Общие состояния

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| COMMON-01 | P0 | Открыть каждый маршрут из карты на production preview, затем пройти между разделами | Нет `pageerror`, не загружаемых JS/CSS и ошибочных chunk-ответов; lazy-страница завершается рабочим экраном |
| COMMON-02 | P1 | По каждому запросу списка/детали воспроизвести медленный ответ, пустой результат и отказ; выполнить доступный повтор | Загрузка, отсутствие данных и ошибка различимы; нет бесконечного spinner; повтор восстанавливает экран без повторного входа |
| COMMON-03 | P1 | Для каждого действия сохранения/отправки нажать кнопку повторно, отменить диалог до отправки, восстановиться после ошибки | Нет дублирующих сущностей от повторного клика; отмена не выполняет действие; ошибка не стирает ввод и не объявляет успех |
| COMMON-04 | P1 | Пройти основные формы, навигацию, меню и диалоги клавиатурой; закрыть через доступные кнопки/Escape | Интерактивные элементы доступны и имеют различимые имена; фокус виден, не уходит под модальное окно и возвращается после закрытия; недостатки фиксируются как дефекты |
| COMMON-05 | P0 | Прогреть данные/черновики пользователя A, выйти и войти B в том же browser context; повторить для двух школ с совпадающими локальными lesson ID | Не показаны чужие школа, роли, уроки, direct-диалоги, локальные черновики и preview. Для редактора ключ только по lesson ID — известный риск, проверка пока не считается пройденной |
| COMMON-06 | P1 | После create/update/delete перейти в связанный раздел, вернуться назад/вперёд, reload | Списки, детали и сводки показывают актуальный результат; нельзя восстановить удалённый объект из старого кеша как существующий |
| COMMON-07 | P1 | Основные пути пройти на desktop и mobile; использовать длинные русские имена/названия, reduced motion | Нет горизонтального скролла документа, перекрытия ввода и недоступных кнопок; ограничение mobile-редактора соблюдено; игра уважает reduced motion |
| COMMON-08 | P0 | Подготовить название/сообщение/имя файла с HTML-разметкой и ссылкой с опасной схемой; открыть их в списке, редакторе, чате и preview | Пользовательский текст не исполняет скрипт; произвольная ссылка не получает авторизованный доступ к чужому origin; ошибки не раскрывают токены, stack trace и технический код пользователю |

Ширины для существующей карточки ожидания уже перечислены в `onboarding.const.ts` тестов. Для остальных экранов использовать отдельные viewport/device-наборы; глобальное включение дополнительных browser-проектов сейчас не требуется для документирования сценариев.

Проверка COMMON-03 является критерием будущих тестов, а не обещанием, что все текущие кнопки уже блокируют повторный клик. Если тест выявит дубль, его нельзя «починить» ожиданием, которое не повторяет действие пользователя.

## Минимальные сквозные истории

Изолированные проверки разделов дополнять несколькими длинными пользовательскими путями. Каждый путь готовит свои данные и очищает их независимо от остальных.

| ID | Приоритет | Подготовка и шаги | Проверяемый итог |
| --- | --- | --- | --- |
| JOURNEY-01 | P0 | Новый пользователь: регистрация → заявка школы → одобрение тестовым служебным пользователем → ожидание создания → «Сегодня» → reload | Пользователь стал владельцем созданной школы, повторный вход не возвращает его к старой заявке |
| JOURNEY-02 | P0 | Владелец: создать приглашение → второй авторизованный аккаунт открывает ссылку → вступает → владелец перечитывает учеников → «Написать» → обмен сообщениями | Вступление реально сохранено, роль правильная, ученик появился в нужной школе, оба получили свои сообщения |
| JOURNEY-03 | P0 | Преподаватель: создать урок → подготовить серверное содержимое через фикстуру → создать курс с этим уроком → назначить ученику → ученик читает → отмечает выполненным → преподаватель смотрит прогресс | Программа, доступ и прогресс согласованы у обоих после reload. Серверную подготовку текста указывать явно: текущая кнопка редактора не публикует локальный черновик |
| JOURNEY-04 | P0 | Преподаватель: создать занятие → ученик видит его в календаре/«Сегодня» → дождаться окна входа → оба открывают одну комнату | Время, участники и room совпадают; реальный токен выдан разрешённым участникам. Проверка аудио/видео добавляется только на медиа-стенде |
| JOURNEY-05 | P0 | Участник: загрузить файл в материалы → открыть чат → прикрепить его → второй участник получает/скачивает → reload у обоих | Доставлено реальное вложение с исходными байтами, связь с сообщением сохранена; посторонний пользователь файл не читает |
| JOURNEY-06 | P0 | Один аккаунт: работа Teacher в A → переход Student в B → чтение урока/курса/чата → выход → вход другим аккаунтом | Переключились данные и права, управление из A не появилось в B, новый аккаунт не увидел старые кеш/черновики |

Полная история «написать текст в редакторе → опубликовать на сервере → ученик видит изменения» блокируется EDITOR-11. Нельзя объявить JOURNEY-03 подтверждением публикации текста, если серверное содержимое было создано фикстурой.
