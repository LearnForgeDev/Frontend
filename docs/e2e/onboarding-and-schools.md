# Подключение школы, приглашения и заявки

Источники: [онбординг](../../src/Services/Onboarding/OnboardingPage.tsx), [хуки онбординга](../../src/Services/Onboarding/hooks), [статусы](../../src/Services/Onboarding/onboarding.const.ts), [хранилище заявки](../../src/Services/Onboarding/utils/schoolRequestStorage.utils.ts), [приглашения](../../src/Services/Schools/SchoolOverview/Components/InviteTokenWidget.tsx), [служебные заявки](../../src/Services/Developer/DeveloperRequestsPage.tsx).

Предусловия: новый пользователь без школ; владелец и преподаватель школы A; независимый аккаунт для вступления. Для переходов статуса нужны реальные подготовленные заявки и служебные права тестового backend. Все решения принимать только для тестовых заявок.

## Онбординг и ожидание

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| ONB-01 | P0 | Новым пользователем без школ открыть `/app` | Открыт `/onboarding`, доступны код приглашения и название новой школы |
| ONB-02 | P1 | Отправить пустое и пробельное название школы; затем заполнить корректное | При пустом значении видна ошибка, заявка не создаётся; корректное имя передаётся без внешних пробелов |
| ONB-03 | P0 | Заполнить название и нажать «Создать школу»; повторный клик во время ожидания | Создана одна заявка с серверным `requestPublicId`; открыт `/onboarding/waiting/R`; указатель заявки относится к текущему пользователю |
| ONB-04 | P0 | Для заявки Pending перезагрузить ожидание; открыть `/onboarding` в той же сессии | Восстановлена та же заявка; нет дублирующей отправки; статус периодически обновляется, приглашение остаётся доступным |
| ONB-05 | P0 | В отдельном служебном контексте одобрить заявку; удержать этап создания школы, затем завершить его | До появления реальной школы показывается подготовка; после появления школы в `my-schools` — переход к её `/today`; старый указатель заявки очищен |
| ONB-06 | P1 | Отклонить/завершить с ошибкой тестовую заявку; затем вернуться через «К моим школам» | Показан отказ, опрос терминального статуса остановлен; можно вернуться в приложение/создать другую заявку без цикла редиректов |
| ONB-07 | P0 | Сохранить указатель заявки аккаунта A; зарегистрировать/войти аккаунтом B; отдельно открыть прямую ссылку на чужую заявку | Заявка A не навязывается B. При отсутствии доступа показана «Не удалось проверить заявку», периодический опрос после ошибки прекращается; введённый код не сбрасывается |
| ONB-08 | P1 | Для своего ожидания воспроизвести ошибку чтения статуса; заполнить приглашение; повторить проверку после восстановления backend | Ошибка видна; поля не исчезают и не очищаются на каждом интервале; повторная попытка восстанавливает корректный статус |
| ONB-09 | P1 | Ожидание с длинным названием открыть на ширинах 360, 768, 1440 | Заголовок, статус и формы доступны, горизонтального скролла документа нет, часы не перекрывают заголовок |
| ONB-10 | P1 | На ожидании нажать «Скоротать время», затем «Начать», управлять Space и touch, дождаться окончания и нажать «Ещё раз»; включить reduced motion | Игровой chunk не загружался до запуска; игра получает фокус, перезапускается; ввод Space/W в поле приглашения не перехватывается игрой; reduced motion скрывает canvas и показывает пояснение |
| ONB-11 | P1 | Пройти выбор школы, Pending, provisioning, Rejected и Approved; проверить индикатор «Прогресс настройки» | Шаги «Аккаунт», «Школа», «Доступ» соответствуют этапу: выбор/отказ — текущая «Школа», ожидание/подготовка — «Доступ», после одобрения и появления школы все шаги завершены; текущий шаг имеет `aria-current="step"` |

Нормализация статусов: `Accepted`/`Pending`/`Processing` — ожидание; `Approved`/`Completed`/`Created` — одобрение с ожиданием появления школы; `Failed`/`Rejected` — отказ. Неизвестный статус сейчас отображается как ожидание, но не входит в набор периодического опроса: это отдельный контракт для уточнения, а не дополнительный успешный статус.

## Приглашения и ученики

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| INV-01 | P0 | Владельцем открыть «Ученики» → «Пригласить в школу», выбрать роль, срок и число входов, создать приглашение | Получен реальный токен, показаны ссылка и QR-код; в ссылке текущий origin и `/onboarding?invite=…`; копирование даёт тот же токен |
| INV-02 | P1 | Повторить создание преподавателем; проверить границы количества/срока и ошибку backend | Преподаватель приглашает ученика, вариант преподавателя доступен владельцу; недопустимые значения не создают приглашение; ошибка не выдаёт ложного успешного результата |
| INV-03 | P0 | Уже авторизованным новым пользователем открыть ссылку; отдельно ввести код вручную с внешними пробелами; нажать присоединение | Код подставлен из URL/очищен при отправке; backend добавляет пользователя с нужной ролью, обновляются сессия и школы; открыта новая школа, доступ сохраняется после reload |
| INV-04 | P0 | **Цель:** гостем открыть приглашение, зарегистрироваться или войти и продолжить вступление | Ожидается сохранение токена через вход. В текущем роутинге токен теряется: фиксировать пробел, не обходить его ручной подстановкой и не считать путь покрытым |
| INV-05 | P1 | По отдельности отправить пустой код, случайный, истёкший, исчерпанный; повторно использовать уже использованный одноразовый код | Пустой код валидируется до запроса; backend отклоняет остальные, доступ не выдаётся; форма остаётся рабочей с понятной ошибкой |
| INV-06 | P1 | Двумя независимыми аккаунтами одновременно использовать последний доступный вход; отдельно присоединиться со страницы ожидания заявки | Лимит токена не превышен; успех виден только реальным участникам. При вступлении из ожидания заявка не должна самопроизвольно отменяться; при следующем входе школа доступна |

Сканирование QR-кода физической камерой не требуется для базового браузерного теста: проверять наличие QR и совпадение его ссылки с выдаваемым приглашением. Физическое сканирование — отдельная проверка устройства.

## Служебные заявки

| ID | Приоритет | Подготовка и действия | Ожидаемый результат |
| --- | --- | --- | --- |
| DEV-01 | P1 | Служебным пользователем открыть `/developer` при наличии тестовых заявок; повторить с пустым списком | Показаны школа, автор и статус каждой заявки; для пустого списка — «Новых заявок нет» |
| DEV-02 | P0 | Выбрать свою тестовую Pending-заявку, нажать «Одобрить», наблюдать её из контекста заявителя | Backend меняет статус, список обновляется; после создания школы заявитель проходит ONB-05; повторное нажатие во время операции заблокировано |
| DEV-03 | P1 | Отклонить отдельную тестовую заявку | Backend сохраняет отказ, список обновляется; заявитель видит ONB-06, школа не появляется |
| DEV-04 | P0 | Открыть `/developer` обычным участником/гостем; отдельно воспроизвести отказ служебной операции | У гостя — вход; у пользователя без прав — сообщение об отсутствии доступа без данных заявок; backend не выполняет approve/reject. Клиентский маршрут защищён только авторизацией, поэтому серверный отказ обязателен |

Управление через внешнюю серверную SoftAdmin не является страницей этого frontend и не входит в его Playwright-каталог.
