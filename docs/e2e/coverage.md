## Ограничения реализации

| Область | Подтверждено кодом | Как учитывать в тестах |
| --- | --- | --- |
| Содержимое урока | `saveEditorState` и автосохранение пишут локальный черновик | EDITOR-02/03 — локальный результат; серверная публикация EDITOR-11 — цель |
| Название урока | Заголовок из router state либо «Урок»; contentEditable не сохраняет metadata | Не выдавать изменение DOM за серверное переименование; reload/чистый контекст выявляют пробел |
| Список уроков | Переименование и перенос — пустые обработчики; старый FileManager не подключён к текущей странице | Нет готового флоу папок, drag-and-drop уроков, поиска/сортировки списка или переноса |
| Мобильный редактор | `getIsMobileDevice` выключает редактирование | Проверять просмотр и уведомление; не писать положительный тест мобильного редактирования |
| Возврат после входа | Защищённый маршрут не сохраняет URL; форма ведёт в `/app` | INV-04 и возврат к комнате после входа требуют реализации |
| Локальные данные | Ключ черновика использует lesson ID; direct-список хранится по school ID | Проверять межпользовательскую/межшкольную изоляцию COMMON-05, не считать её гарантированной |
| Курсы | Frontend имеет roster/progress и составные операции; CI-backend закреплён отдельно | До автоматизации подтвердить контракт и расширить seed, не подменять отсутствующий API happy-path моками |
| Звонки | В CI `Jitsi__PublicUrl=https://meet.invalid` | Доказана только выдача токена; CALL-05/08 требуют другого стенда |
| Служебные заявки | Маршрут требует входа; служебные полномочия проверяет backend; seed содержит лишь три обычные роли | Добавить отдельного пользователя и тесты реального запрета |
| Расписание | Участники нового занятия формируются автоматически; удаления с подтверждением нет | Не описывать выбор отдельных участников, повторение событий и подтверждение удаления как имеющиеся действия |
| Чат | Страница и мини-виджет имеют разные формы ввода | Лимиты/многострочность проверять именно в подключённой форме, не по соседнему компоненту |

В каталог не включены неподключённые экраны Settings/SchoolOverview как отдельные страницы, старые админские dashboard-компоненты, маркетплейс, совместная доска, редактирование профиля и аватара, редактирование/удаление сообщений, задания и оценки. Их наличие в старом README, исходниках или API не доказывает пользовательский путь.

## Порядок расширения

1. **P0 доступа и сессии:** сохранить existing smoke, добавить реальную вторую школу, независимые контексты, отказ API, offline/retry и изоляцию после смены аккаунта.
2. **P0 повседневной работы:** UI-download/delete материалов, получатель SignalR, приглашение/вступление, update/delete расписания и точные участники.
3. **P0 новых контрактов:** реальный backend/seed для курсов и служебных заявок, затем JOURNEY-01–06. Серверное сохранение текста требует сначала реализовать EDITOR-11.
4. **P1:** форматирование/вложения редактора, ошибки по разделам, mobile/keyboard/reduced motion, границы даты и времени.
5. **Отдельный стенд:** Jitsi медиа, физическая камера/QR и зависимые внешние сервисы. Их результаты не смешивать с базовым production-preview CI.

Локально тяжёлые CI-задачи не запускать. При реализации новых тестов проверять их в существующем workflow и сохранять отчёт/trace; этот каталог сам по себе не увеличивает фактическое браузерное покрытие.
